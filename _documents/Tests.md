# Tests.md

Тестовые сценарии описываются здесь. Это не код тестов.

## Agent Workflow

- Проверить, что пользователь может дать большую задачу через `tz.md` без ручного заполнения `_documents/TASKS.md`.
- Проверить, что агент задает уточняющие вопросы, если без них нельзя сформировать acceptance criteria.
- Проверить, что агент сам обновляет `_documents/PRD.md`, `_documents/TASKS.md` и `_documents/Tests.md` после анализа входа.
- Проверить, что агент выбирает только задачи со статусом `Ready`.
- Проверить, что агент не берет больше 3 задач за итерацию.
- Проверить, что после выполнения агент обновляет `_documents/CHANGELOG.md`, `_documents/Tests.md`.
- Проверить, что после завершения всех задач агент очищает активную секцию `_documents/TASKS.md`.
- Проверить, что агент не создает в корне `PRD.md`, `TASKS.md`, `Tests.md`, `CHANGELOG.md`, `AGENT_SKILL.md`.

## API

- Проверить успешный ответ health-check endpoint после его появления.
- Проверить обработку ошибок валидации после появления API.

## UI

- Проверить загрузку главной страницы после появления frontend.
- Проверить базовый пользовательский сценарий после его описания в `_documents/PRD.md`.

## Инфраструктура

- Проверить запуск Docker Compose через `infra/docker/docker-compose.yml`.
- Проверить, что корневой `docker-compose.yml` отсутствует и не создается агентом без отдельной явной задачи.
- Проверить доступность postgres и redis внутри docker-сети.
