# AGENT_SKILL.md

## Назначение

Этот файл описывает, как агент должен работать с задачей от входа до результата.

Использовать при любом новом входе (tz.md или сообщение пользователя).

---

## Общий принцип

Работа всегда идет по цепочке:

`tz.md` → `_documents/PRD.md` → `_documents/TASKS.md` → выполнение → `_documents/CHANGELOG.md`

---

## Шаг 1. Intake (разбор входа)

1. Прочитать:
   - tz.md (если есть)
   - _documents/PRD.md
   - _documents/TASKS.md
   - _documents/Tests.md
   - _documents/CHANGELOG.md

2. Определить:
   - цель
   - результат
   - ограничения
   - неясности

3. Если есть критичные неясности → задать вопросы и остановиться

4. Если неясности некритичны → зафиксировать допущения и продолжить

---

## Шаг 2. Планирование

1. Обновить `_documents/PRD.md`, если вход расширяет контекст  
   (НЕ придумывать новый продукт)

2. Сформировать `_documents/TASKS.md`

---

### Формат задач

Каждая задача:

- id
- статус: Ready / In Progress / Done / Blocked
- краткое описание
- acceptance criteria (1–3 пункта)
- способ проверки

---

### Правила задач

- задача должна быть выполнима за одну итерацию
- максимум 3–5 файлов изменений
- если больше — разбить
- не добавлять задачи вне входа

---

## Шаг 3. Обновление тестов

Обновить `_documents/Tests.md`:

- добавить сценарии проверки
- сгруппировать логически
- не писать код тестов

---

## Шаг 4. Выполнение

Работать батчами:

1. взять 1–3 задачи со статусом Ready
2. перевести их в In Progress
3. реализовать
4. выполнить минимальные проверки
5. перевести задачи в Done

---

## Шаг 5. Фиксация

После выполнения:

1. Обновить `_documents/CHANGELOG.md`:

формат:
- дата
- короткое описание

2. Обновить `_documents/Tests.md` при изменении поведения

---

## Структурные ограничения

- Рабочие документы хранятся только в `_documents/`
- В корне разрешен только входной `tz.md`
- Не создавать в корне `PRD.md`, `TASKS.md`, `Tests.md`, `CHANGELOG.md`, `AGENT_SKILL.md`
- Если такие файлы уже есть в корне, остановиться и предложить перенос в `_documents/`
- Docker Compose хранится только в `infra/docker/docker-compose.yml`
- Не создавать корневой `docker-compose.yml` без отдельной явной задачи

---

## Изменения вне задачи

Разрешены только если необходимо для:

- сборки
- тестов
- интеграции
- устранения явной ошибки

Обязательно кратко объяснить причину.

---

## Ограничения

НЕЛЬЗЯ:

- писать код вне `_documents/TASKS.md`
- менять продуктовую логику без входа
- трогать несвязанные части
- делать "улучшения без задачи"

---

## Когда остановиться

Остановиться и спросить, если:

- неясен результат
- нет acceptance criteria
- задача слишком большая
- конфликт с `_documents/PRD.md`
- нужны секреты или доступы

---

## Definition of Done

Задача завершена, если:

- выполнены acceptance criteria
- статус обновлен
- обновлен `_documents/CHANGELOG.md`
- обновлен `_documents/Tests.md`
- проверки выполнены или указана причина

---

## Завершение цикла

Если все задачи выполнены:

- `_documents/TASKS.md` очищается
- система возвращается в ожидание нового tz.md
